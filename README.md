## Released Products

### 🛡️ AegisLog v2.1.17

**Free, open source defensive log investigation in your terminal.**

AegisLog helps users investigate supported log files and accessible **Windows Event Logs, Linux journald and Docker telemetry**. It analyzes sources locally and handles them as read only.

**Who it helps**

System administrators reviewing service failures, developers investigating application errors, security analysts examining supported authentication and security signals, and students learning evidence based log investigation.

**What it provides**

File analysis · folder investigations · guided computer checks · single source and multiple source live monitoring · deterministic findings · incident grouping · investigation timelines · entity context · evidence supported MITRE ATT&CK mappings

Users can review findings and recommended next steps, search saved cases, compare activity baselines and generate **HTML investigation summaries and complete retained evidence reports**. Aggregate sharing summaries provide a separate export with identifying details and raw evidence omitted.

**Latest release**

Version **2.1.17** adds JSON limits enforced during reading, bounded custom rule packs and restricted custom regex syntax. It preserves the approved terminal navigation and report appearance.

**Availability**

Free · open source · MIT licensed · standalone Windows executable · Windows ZIP · Python packages

Windows executable users do not need Python. Python users can install through pipx and run `aegislog start` in their existing terminal.

> [!IMPORTANT]
> **Local · Read only · Deterministic**
> AegisLog supports investigation without changing source logs or performing automatic remediation. Its supported product surface has no browser dashboard or remote AI dependency.

> [!NOTE]
> Findings are investigation leads, not proof of compromise. Rarity scores describe the retained sample, not attack probability. Source permissions, supported formats and evidence limits affect coverage.

## Engineering & Release Practice

We develop software with attention to **repeatable builds, readable workflows and verifiable releases**.

Depending on the product, our process includes automated tests, linting, security checks, dependency auditing, package validation, executable builds, smoke tests, checksums and release documentation.

For **AegisLog v2.1.17**, the release pipeline validates version metadata, tests Python packages and the Windows executable, and checks installation, command navigation and report output.

Publication verifies **all seven release assets** against reviewed digests and matching checksum files, including the bundled executable. Protected main branch updates require review and passing checks.

> [!TIP]
> Download AegisLog from its official release page and compare the checksum for the exact asset you downloaded. SHA-256 checksums verify file bytes; they do not establish publisher identity. The Windows executable remains unsigned.

> [!NOTE]
> Automated tests and synthetic detection evaluations establish regression consistency. They do not establish independent real world detection effectiveness or compatibility with every physical PC and terminal.

## Engineering Principles

**Defensive by design**

Security tools should support investigation without overstating certainty.

**Local processing where practical**

Sensitive information should remain under the user's control whenever possible.

**Security aware development**

Testing, static analysis, dependency checks and careful data handling are part of development.

**Release discipline**

Packaging, documentation, versioning and release verification matter alongside feature development.

**Readable experiences**

Technical tools should explain their findings, supporting evidence and limitations.

**Standards with context**

Frameworks guide engineering decisions without implying certification.

**Continuous learning**

Technical study is applied through builds, experiments, reviews and improvements.
